
# 08. 成績管理アプリの面接対策

## 1. この資料の目的

この資料では、C#で開発した学生成績管理アプリについて、採用面接で説明できるように開発の目的、実装した機能、設計上の工夫、苦労した点、今後の改善点を整理する。

今回の開発では、C#を使用して学生情報の登録・表示・検索・編集・削除を行うコンソールアプリを作成した。

さらに、JSON形式によるデータ保存・読み込み機能を追加し、アプリを終了しても学生情報を保持できるようにした。

今後はASP.NET Coreを利用し、ブラウザから操作できるWebアプリへの発展を目指している。

## 3. なぜこのアプリを開発したのか

### 開発の目的

C#の基本的な文法を学ぶだけでなく、実際に動作するアプリケーションを自分で作成することで、プログラミングの理解を深めたいと考えた。

そこで、学生の名前や各科目の点数を管理する成績管理アプリを開発することにした。

この題材を選んだ理由は、データの登録・表示・検索・編集・削除という、業務システムでも利用される基本的な処理を一通り学習できるためである。

また、最初はシンプルなコンソールアプリとして開発し、機能を段階的に追加する方針にした。

## 4. プログラムの設計

### Studentクラス

Studentクラスでは、学生1人分の情報を管理する。

```csharp
class Student
{
    public string Name { get; set; } = "";
    public int MathScore { get; set; }
    public int EnglishScore { get; set; }
    public int JapaneseScore { get; set; }

    public double GetAverage()
    {
        return (MathScore + EnglishScore + JapaneseScore) / 3.0;
    }
}
```

学生の名前や各科目の点数をプロパティとして管理し、平均点を計算するメソッドも定義した。

### Programクラス

Programクラスでは、アプリ全体の処理を管理する。

```csharp
static List<Student> students = new List<Student>();
```

List<Student></student>を使用して、複数の学生情報を管理している。

また、登録・表示・検索・編集・削除などの処理を、それぞれ独立したメソッドに分けた。

### メソッドを分けた理由

すべての処理をMain()に記述すると、コードが長くなり、内容を把握しにくくなる。

そのため、機能ごとにメソッドを分けることで、プログラムの見通しを良くし、修正や機能追加をしやすくすることを意識した。

## 5. 開発で工夫した点

### ① 点数の入力チェック

点数の入力では、int.TryParse()を利用して整数に変換できるかを確認した。

さらに、0～100点の範囲に収まっているかを確認することで、不適切な点数が登録されないようにした。

```csharp
if (int.TryParse(input, out int score))
{
    if (score >= 0 && score <= 100)
    {
        return score;
    }
}
```

単に入力された値を登録するのではなく、適切なデータか確認することを意識した。

### ② 平均点の計算

平均点を計算する際には、整数同士の割り算によって小数部分が失われないように、3.0で割る方法を採用した。

```csharp
return (MathScore + EnglishScore + JapaneseScore) / 3.0;
```

これにより、小数点以下を含む平均点を計算できる。

### ③ 機能ごとのメソッド分割

学生情報の登録・表示・検索・編集・削除をそれぞれ別のメソッドに分けた。

これにより、処理の役割を明確にし、特定の機能だけを修正しやすくした。

### ④ JSONによるデータ保存

当初はList<Student></student>で学生情報を管理していたが、アプリを終了するとデータが消えてしまうという課題があった。

そこで、System.Text.Jsonを利用してJSON形式でデータを保存する機能を追加した。

学生情報の登録・編集・削除後に保存し、アプリ起動時に読み込む仕組みとした。

その結果、アプリを再起動しても学生情報を保持できるようになった。

## 6. 開発中に直面した問題と対応

### ① データがアプリ終了後に消える問題

**問題**

最初の実装では、学生情報をList<Student></student>で管理していたため、アプリを終了すると登録した情報が失われた。

**対応**

JSON形式でファイルに保存する仕組みを追加した。

**学んだこと**

アプリケーション内でデータを管理することと、アプリ終了後もデータを保持することは別の問題であると理解した。

### ② 入力値によるエラーへの対応

**問題**

点数に文字列や範囲外の数字が入力される可能性があった。

**対応**

int.TryParse()と条件分岐を利用して、入力値が整数であり、0～100点の範囲内であるか確認するようにした。

**学んだこと**

正常な入力だけでなく、想定外の入力に対応することが重要だと理解した。

### ③ 削除処理におけるリストの扱い

**問題**

foreachでリストを列挙している最中に要素を削除すると、コレクションの変更に関する例外が発生する可能性がある。

**対応**

削除機能ではfor文を利用し、インデックスを指定してRemoveAt()を実行する方法にした。

**学んだこと**

コレクションを操作する際には、列挙処理と要素の変更方法に注意する必要があると理解した。

### ④ ビルド時に実行ファイルがロックされる問題

**問題**

dotnet buildを実行した際、StudentGradeApp.exeが別のプロセスによって使用されており、ビルドに失敗したことがあった。

**対応**

実行中のアプリケーションを終了し、必要に応じてtaskkillコマンドで該当プロセスを終了してから再度ビルドした。

**学んだこと**

プログラムのコードに問題がなくても、実行中のプロセスなど開発環境側の要因でビルドに失敗することがあると学んだ。

## 8. 現在のアプリの課題

今回のアプリは学習用の基本的な機能を実装した段階であり、実用的な業務システムにするためには改善が必要である。

| 課題                             | 改善案                              |
| -------------------------------- | ----------------------------------- |
| 学生を名前だけで識別している     | 学生IDを導入する                    |
| 同姓同名の学生を区別しにくい     | 一意のIDによる検索・編集・削除      |
| 削除前の確認がない               | 削除確認画面を追加                  |
| JSONファイルに依存している       | SQLiteなどのデータベースを導入      |
| JSON読み込み失敗時の保護が不十分 | バックアップや起動中断などを実装    |
| コンソールで操作する             | ブラウザから操作できるWeb画面に変更 |
| テストが手動中心                 | 自動テストを導入                    |

特に、JSONファイルの読み込みに失敗した場合、現在の実装では空のリストにして処理を続ける。その後に保存操作を行うと、元のデータを上書きする可能性がある。

そのため、今後はデータを保護する仕組みを改善したい。

## 9. 今後の開発計画

今後は、現在のC#成績管理アプリを土台として、ASP.NET Core Razor PagesによるWebアプリ化を目指している。

### 開発予定

1. ASP.NET Core Razor Pagesのプロジェクトを作成する。
2. HTMLとCSSを利用して学生一覧画面を作成する。
3. 学生情報の登録フォームを実装する。
4. 学生情報の検索・編集・削除を実装する。
5. SQLiteなどのデータベースを導入する。
6. GitHubでソースコードを管理し、READMEを整備する。

### Webアプリ化する理由

コンソールアプリでは、PowerShellから文字列や数字を入力して操作する必要がある。

Webアプリにすることで、ブラウザ上に学生情報を表形式で表示し、ボタンや入力フォームから操作できるようになる。

また、Webアプリ開発を通じて、C#だけでなくHTML・CSS・HTTP・データベースなどの知識も身につけたいと考えている。
